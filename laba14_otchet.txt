Лабораторная работа №14. Обработка JSON файлов.
Группа: ИСТбд-22. Вариант: 9 «Список команды».
Автор: Калинин Вячеслав.

1. ПОСТАНОВКА ЗАДАЧИ
--------------------
Структура данных (лыжник): ФИО лыжника; разряд; срок достижения
максимальной спортивной формы (нед.); срок сохранения максимальной
спортивной формы (нед.); победы.
Ввод: начало и конец соревнования. Недели «до пика формы» отсчитываются
от даты начала подготовки, поэтому она тоже вводится.
Обработка:
  - распределение лыжников по максимальной спортивной форме в течение
    соревнований;
  - формирование команды: 5 человек основной состав, 2 резерв.
Приложение с графическим интерфейсом tkinter: ввод и накопление данных,
сохранение в JSON, загрузка из JSON, обработка по варианту, визуализация
набора данных и результатов. pandas не используется.
Кнопки: импорт JSON в БД, сохранить в JSON, просмотр БД, вычислить
значения, ввести запись, перейти к записи, редактировать запись,
удалить запись, поиск по полям, очистить БД.
Окна: БД, вычисленные характеристики (текст и диаграмма), поля поиска и
редактирования.

2. АРХИТЕКТУРА ПРИЛОЖЕНИЯ
--------------------------
За основу взята структура лабы 12: однофайловое приложение (laba14.py),
два слоя.
  - backend: функции работы с JSON (модуль json) и с БД SQLite (sqlite3):
    класс Lyzhnik (проверка и приведение типов одной записи), загрузка и
    сохранение JSON, CRUD-операции, поиск, очистка и функция
    analiz_variant_9, выполняющая расчёт на Python;
  - frontend: класс Prilozhenie(tk.Tk) — панель кнопок, поля дат
    соревнования, вкладки «БД», «Вычисленные характеристики»,
    «Диаграмма формы» и форма поиска/редактирования.
Данные хранятся в komanda.db рядом со скриптом. Пример набора — komanda.json.
Поток данных:
  JSON -> zagruzit_json -> объекты Lyzhnik -> таблица lyzhniki (БД)
  БД -> analiz_variant_9 -> текст результатов + диаграмма
  БД + даты + результат -> sohranit_json -> JSON

Формат JSON:
  {
    "sorevnovanie": {"podgotovka": "02.11.2026",
                     "nachalo": "04.01.2027", "konec": "24.01.2027"},
    "lyzhniki": [{"id": 1, "fio": "...", "razryad": "МС",
                  "do_formy": 9, "v_forme": 4, "pobedy": 12}, ...],
    "rezultat": {...}   - добавляется при сохранении после расчёта
  }
Импорт понимает и просто список лыжников без "sorevnovanie".

3. ПРОЕКТНЫЕ РЕШЕНИЯ FRONTEND
------------------------------
- Кнопки расположены в два ряда по 5, справа — статус (число записей
  или найденных).
- Отдельная рамка «Соревнование» с тремя полями дат (ДД.ММ.ГГГГ);
  при импорте JSON даты подставляются из файла.
- ttk.Notebook с тремя вкладками:
  «БД» — ttk.Treeview со скроллбаром;
  «Вычисленные характеристики» — Text: рейтинг лыжников с пиком формы,
  числом дней в форме и статусом, итоги по группам, по неделям
  соревнования и состав команды;
  «Диаграмма формы» — Canvas: по горизонтали недели от начала
  подготовки, синим выделен период соревнования, у каждого лыжника полоса
  его пика формы (зелёный — основной состав, оранжевый — резерв, серый —
  не в команде). Перерисовывается при изменении размера окна.
- Поля поиска и редактирования: разряд выбирается из выпадающего списка
  (ttk.Combobox), остальное — Entry. Клик по строке таблицы копирует
  запись в поля.
- «Ввести запись» с пустым № — номер присваивается автоматически.
- Удаление и очистка БД требуют подтверждения; ошибки ввода (не число,
  отрицательное значение, неверный разряд или дата, конец раньше начала,
  битый JSON) показываются в messagebox.
- После изменения данных старый результат сбрасывается, чтобы в JSON не
  попал неактуальный расчёт.

4. ПРОЕКТНЫЕ РЕШЕНИЯ BACKEND
-----------------------------
- Таблица lyzhniki: id INTEGER PRIMARY KEY (автонумерация), fio, razryad,
  do_formy, v_forme, pobedy. Запросы параметризованы (?).
- Импорт: json.load -> проверка структуры -> Lyzhnik для каждой записи
  (ошибка сообщает номер записи) -> INSERT OR REPLACE (повторный импорт не
  дублирует записи).
- Сохранение: json.dump(ensure_ascii=False, indent=2) — кириллица
  читается в файле как есть.
- Разряды упорядочены от сильного к слабому: МСМК, МС, КМС, I, II, III,
  б/р (1/2/3 принимаются как I/II/III).
- Расчёт (analiz_variant_9), модуль datetime:
  1) пик формы: с (подготовка + do_formy недель) по
     (начало пика + v_forme недель - 1 день);
  2) дни в форме на соревновании = длина пересечения пика с
     [начало; конец] включительно;
  3) статус: «весь период», «частично», «пик до старта»,
     «пик после финиша»; группировка по статусам;
  4) по каждой неделе соревнования — кто в пике хотя бы один день;
  5) рейтинг: больше дней в форме -> выше разряд -> больше побед;
     первые 5 — основной состав, следующие 2 — резерв. Если лыжников
     меньше 7 или в команду попал лыжник вне формы — выводится
     предупреждение.

5. ПРОВЕРКА
-----------
Пример komanda.json: 10 лыжников, подготовка с 02.11.2026, соревнование
04.01.2027 - 24.01.2027 (21 день).
Весь период в форме — 2 (Иванов, Смирнов), частично — 6, пик до старта —
1 (Михайлов), пик после финиша — 1 (Новиков). По неделям: 5, 5, 4 чел.
Основной состав: Иванов, Смирнов, Кузнецов, Соколов, Васильев.
Резерв: Морозов, Попов (у Васильева, Морозова, Попова и Фёдорова по 7 дней —
отбор решили разряд и число побед).
Проверены: импорт и повторный импорт, сохранение в JSON с результатом и
обратное чтение, поиск (ФИО по подстроке + разряд), ввод записи без
номера, ошибка «конец раньше начала», импорт не-JSON файла.
